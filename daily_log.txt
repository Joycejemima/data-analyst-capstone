2. OLIST DATASET (from Kaggle, 9 CSV files)
orders (99,441 rows, one row per order)
- Columns: order_id, customer_id, order_status, order_purchase_timestamp,
  order_approved_at, order_delivered_carrier_date,
  order_delivered_customer_date, order_estimated_delivery_date
- Statuses: approved, canceled, created, delivered, invoiced,
  processing, shipped, unavailable
- Undelivered orders have blank delivery dates

customers (99,441 rows)
- Columns: customer_id, customer_unique_id, customer_zip_code_prefix,
  customer_city, customer_state
- customer_id is unique per order; customer_unique_id identifies the person
- 96,096 unique customers, 3,345 repeat orders (about 3%), so retention is low

order_items (112,650 rows, one row per item in an order)
- Columns: order_id, order_item_id, product_id, seller_id,
  shipping_limit_date, price, freight_value
- order_item_id is the line number within an order (1, 2, 3...)
- Primary key: order_id + order_item_id together (composite key)
- To verify: about 98,666 unique orders here vs 99,441 in orders

3. KEY CONCEPTS
- Primary key: identifies exactly one row (no duplicates)
- Foreign key: holds values from another table's primary key, links tables
- Links: orders.customer_id -> customers; order_items.order_id -> orders,
  product_id -> products, seller_id -> sellers
- One-to-many: one order can have many item rows
- After a join, check whether the row count changed before summing
