3. KEY CONCEPTS
- Primary key: identifies exactly one row (no duplicates)
- Foreign key: holds values from another table's primary key, links tables
- Links: orders.customer_id -> customers; order_items.order_id -> orders,
  product_id -> products, seller_id -> sellers
- One-to-many: one order can have many item rows
- After a join, check whether the row count changed before summing

DAY 2 NOTES (29 Sep 2026)

1. TOPICS LEARNED
- Tables (Ctrl+T): auto-expanding range, built-in filters, banded rows
- Sorting: single-column (A-Z button) vs multi-level sort (Data > Sort >
  Add Level) for "sort by X, then by Y"

  (depends on whether the column is a real date)
- Absolute vs relative references: $A$1 stays fixed when copied, A1
  shifts. Use F4 to toggle. Needed when a formula refers to one fixed
  cell (like a tax rate) while other parts shift down rows.

3. KEY MISTAKE AND FIX (important habit)
- Used Ctrl+Down while a filter was active - this jumps to the last
  row of the WHOLE table, not the last VISIBLE row, so it silently
  ignores the filter and gives a wrong (too-high) count
- Fix: use a formula instead of reading filtered/sorted views:
  - COUNTIF(range, "value") - count matching rows directly
  - COUNTIFS(range1, cond1, range2, cond2) - multiple conditions
  - COUNTBLANK(range) - count empty cells
  - SUBTOTAL(103, range) - counts only visible rows if a filter IS
    active and you want that
- Habit: cross-check any count against a total or another known
  number before trusting it. If a "subset" count is suspiciously
  close to the full total, it's probably wrong.
