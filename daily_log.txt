3. KEY MISTAKE AND FIX (important habit)
- Used Ctrl+Down while a filter was active - this jumps to the last
  row of the WHOLE table, not the last VISIBLE row, so it silently
  ignores the filter and gives a wrong (too-high) count
- Fix: use a formula instead of reading filtered/sorted views:
  - COUNTIF(range, "value") - count matching rows directly
  - COUNTIFS(range1, cond1, range2, cond2) - multiple conditions
  - COUNTBLANK(range) - count empty cells
  - SUBTOTAL(103, range) - counts only visible rows if a filter IS
    active and you want that
- Habit: cross-check any count against a total or another known
  number before trusting it. If a "subset" count is suspiciously
  close to the full total, it's probably wrong.

1. TOPICS LEARNED

2. APPLIED ON orders_practice.xlsx
- Built delay_days column (I): =IF(G2="","Not delivered",G2-H2)

3. KEY BUG FOUND (important Excel quirk)
- IF(I2>0,...) on a column with mixed text/numbers gave wrong
  results: Excel treats ANY text as "greater than" any number, so
  "Not delivered" > 0 evaluated to TRUE, wrongly marking undelivered
  orders as "late"
- Fix: check for the text case FIRST with a nested IF:
  =IF(I2="Not delivered","No",IF(I2>0,"Yes","No"))
- Lesson: when a column mixes text and numbers, always guard against
  the text case before doing a numeric comparison

1. TOPICS LEARNED
- COUNTIFS: count rows matching multiple conditions
  =COUNTIFS(range1, cond1, range2, cond2, ...)
- SUMIFS: sum a range where multiple conditions are met - sum range
  comes FIRST, before any condition pairs
  =SUMIFS(sum_range, range1, cond1, range2, cond2, ...)
- AVERAGEIFS: same shape as SUMIFS, but averages instead of summing
- All condition ranges must be the same size as each other and as
  the sum/average range, a mismatch is a common error
- A single range can take two conditions at once (e.g. ">=50" and
  "<=100" on the same column) to build a "between" check
- FORMULATEXT(cell): shows another cell's formula as text, useful
  for keeping a readable record of answer + formula side by side

DAY 5 NOTES (02 Oct 2026)

1. TOPICS LEARNED
- XLOOKUP: not available on this laptop (#NAME? error means the
  Excel version doesn't have it - needs Microsoft 365/2021/2024).
  Free workaround: Excel for the web (office.com) always has it.
- INDEX-MATCH: used instead, works in every Excel version, does the
  same job as XLOOKUP in two steps:
  - MATCH(lookup_value, lookup_range, 0) finds a POSITION (a row
    number), not a value. The 0 means exact match.
  - INDEX(return_range, row_number) returns the value sitting at
    a given position
  - Combined: =INDEX(return_range, MATCH(lookup_value, lookup_range, 0))
  - Practiced first on a small 5-row sample table before using it
    on real data
- VLOOKUP pitfalls (good to know, not using it going forward):
  - Can only look to the RIGHT of its search column
  - Uses column NUMBERS, so inserting/reordering columns silently
    breaks it (wrong answer, no error)
  - Easy to forget the exact-match argument (FALSE), defaults to
    an approximate match that looks right but isn't
  - Slower on large datasets than INDEX-MATCH/XLOOKUP
- Cross-file formulas: INDEX-MATCH can reference a different open
  workbook, e.g. '[customers_practice.xlsx]Sheet1'!$E:$E - but this
  is fragile, breaks if the file is moved/renamed. Power Query
  (Week 2) solves this properly with a saved, repeatable connection.

3. BUG FOUND: stale Pivot Table cache
- order_month didn't show up in the Pivot Table Field List, even
  after refreshing and even in a brand-new Pivot Table
- Cause: when a column is inserted in the MIDDLE of a Table (not
  added at the end), Excel can reuse an old, stale Pivot Cache
  instead of rebuilding one from the table's current columns - a
  known Excel quirk
- Fix: delete every existing Pivot Table (all sheets holding one),
  save, fully close and reopen Excel (clears the in-memory cache
  too), then insert a completely fresh Pivot Table
- Lesson: a Pivot Table's field list can lag behind real data even
  after a manual refresh - if a column is missing, the cache itself
  (not the data) is the first thing to suspect, especially for
  mid-table column insertions
